# Yield Tracker

Yield Tracker records cultivation harvests and summarizes yield. A React app lists harvests, accepts new entries, and shows totals. A FastAPI backend stores those records in PostgreSQL. A small command-line script can still summarize plant counts from a local CSV.

## What it does

- Store each harvest: dates, cycle, strain, grade A grams, extraction grams, plant count, average potency, and grams per plant.
- List harvests and filter them in the browser by cycle number or strain.
- Add a harvest from the form. When the plant count is greater than zero, grams per plant is `(grade A grams + extraction grams) / plant count`.
- Show totals for grade A grams, extraction grams, and plant count, plus average grams per plant and the top strain by combined grams.
- Print plant counts grouped by strain from `harvests.csv`, without using the API or the database.

The like button on a harvest card stays in the browser. It is not saved.

## Requirements

- Python 3.10 or newer. The virtualenv in this folder uses Python 3.13.7.
- Node.js 22 and npm. This app was run with Node.js 22.15.0.
- A PostgreSQL database and a SQLAlchemy connection string.

## Setup

Commands below are for PowerShell, run from the repository root unless a step says otherwise.

### Backend

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r "backend\python\requirements.txt"
```

Create `backend\python\.env` with the database URL:

```text
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/DATABASE
```

`database.py` loads that file and opens the SQLAlchemy engine from `DATABASE_URL`. Use the URL from your database host. `postgresql://` also works here because `psycopg2` is installed. Do not commit the file.

The API expects a `harvests` table. It does not create one. For a new PostgreSQL database:

```sql
CREATE TABLE harvests (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    harvest_date DATE NOT NULL,
    trim_start_date DATE NOT NULL,
    cycle_number VARCHAR(50) NOT NULL,
    strain VARCHAR(50) NOT NULL,
    grade_a_grams DOUBLE PRECISION,
    extraction_grams DOUBLE PRECISION,
    plant_count INTEGER,
    avg_potency_pct DOUBLE PRECISION,
    grams_per_plant DOUBLE PRECISION
);
```

Start the API from `backend\python` so `database` imports resolve:

```powershell
cd "backend\python"
..\..\venv\Scripts\Activate.ps1
uvicorn main:app --reload
```

The API listens on `http://127.0.0.1:8000`. Interactive docs are at `http://127.0.0.1:8000/docs`.

### Frontend

Create `frontend\.env`:

```text
VITE_API_URL=http://127.0.0.1:8000
```

Then install and start the app:

```powershell
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The API allows browser requests from that origin and from `https://yield-tracker-1.onrender.com`. Another local origin needs to be added to `allow_origins` in [backend/python/main.py](backend/python/main.py). Restart `npm run dev` after changing `VITE_API_URL`.

Other frontend scripts:

```powershell
npm run build
npm run preview
npm run lint
```

## API

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/` | Returns `{"message": "Yield found"}` |
| `GET` | `/harvests` | Returns every harvest row |
| `POST` | `/harvests` | Creates one harvest and returns the saved row |
| `GET` | `/stats` | Returns totals and the top strain |

`GET /stats` includes only rows whose `plant_count` is not null. Average grams per plant is `(sum of grade A + sum of extraction) / sum of plant count` for those rows. The top strain is the one with the highest combined grade A and extraction grams.

Example create body:

```json
{
  "harvest_date": "2026-09-09",
  "trim_start_date": "2026-10-05",
  "cycle_number": "5A.09092026",
  "strain": "Candy Cake",
  "grade_a_grams": 4623,
  "extraction_grams": 1910,
  "plant_count": 40,
  "avg_potency_pct": 30.63,
  "grams_per_plant": 163.325
}
```

Dates use `YYYY-MM-DD`. Numeric fields may be omitted or null. The database still requires `harvest_date`, `trim_start_date`, `cycle_number`, and `strain`.

## Harvest fields

| Field | Meaning |
| --- | --- |
| `harvest_date` | Date the plants were harvested |
| `trim_start_date` | Date trimming started |
| `cycle_number` | Cultivation cycle identifier |
| `strain` | Strain name |
| `grade_a_grams` | Grade A yield in grams |
| `extraction_grams` | Extraction yield in grams |
| `plant_count` | Number of plants. The CSV report calls this column `plants` |
| `avg_potency_pct` | Average potency percentage |
| `grams_per_plant` | Yield in grams per plant |

## CSV report

[backend/python/report.py](backend/python/report.py) reads `harvests.csv` from the current working directory. Run it from the repository root:

```powershell
python "backend\python\report.py"
```

The CSV needs a header with `strain` and `plants`. The sample file also has `harvest_date`, `trim_start_date`, `cycle_number`, `grade_a_grams`, `extraction_grams`, `avg_potency_pct`, and `grams_per_plant`. Only `strain` and `plants` are used.

The script prints the total plant count, then the count for each strain. Matching strain names are combined across cycles. A blank `plants` cell is skipped, and the script prints the strain name. Any other `plants` value must be a whole number.

`harvests.csv` is gitignored, so a local copy is not part of the repository.
